# E：候选包、许可隐私终审、独立运行与真实读者审阅

状态：待 D 完成且所有者指派。按 E1 → E2 → E3 → E4 → E5 执行，不同时开启 F。

## E1：候选范围与提交身份

审阅 PUBLICATION-FILES、Ledger、D/P 记录、[许可预审](../evidence/LICENSING-REVIEW.md)和[依赖处理](../evidence/DEPENDENCY-GAPS.md)。
分别明确源码公开集合、Windows x64 运行包、可选证据附件；GitHub 自动源码 ZIP 不等于可运行包。
用明确文件清单生成候选，不使用整个工作树、git add . 或把 out 全量打包。检查路径逃逸、链接/联接点、缺失文件和 hash。
先备好提交范围/diff与验证，再取得本地 commit 授权，建立 LumaBough 自己的提交身份，不导入 MiniEngine 历史。
重新 configure/build 以避免嵌入陈旧提交；绑定实际运行提交、二进制和输入。相关内容/EXE 改变时按交接入口规则返验 P/D。
仅哈希关联到旧源码的结果仍可作为旧快照证据，但不得标为最终包的实测结果。

## E2：打包与再分发检查

实现可重复、输入显式的候选打包步骤；产出包内逐文件 manifest、SHA-256 清单、构建/运行说明、许可证和真实支持矩阵。
核对实际携带的 VC Runtime、DXC/SDK、WinPixEventRuntime 等 DLL 及传递依赖，不能因开发机可运行就遗漏。
查阅实际版本的官方再分发条款及随包许可；不能把开发工具、SDK 或编译器整体复制入包。证据不足则排除该附件或保留 BLOCKED。
检查源/烘焙资产、署名、第三方 notices、Capture 中资源、字体、视频素材。MIT 只覆盖自有部分。
不默认装包即有 glTF Validator/VS/资产源树；运行包应携带可运行的已烘焙资源或明确且实测的准备步骤。
检查 M610_PROJECT_ROOT 等编译期绝对路径、运行时 scene/shader/asset 查找和 M7 固定 out 路径；需要修复则记录源码变化并重新构建验证。

## E3：隐私与内容终审

对源码集合、Git 待提交内容和包解压后的实际字节分别审查：私人记录、机器名/用户名/绝对路径、token、缓存、日志、PDB、旧仓库信息、原始 Capture/视频。
自动扫描只产生待审项，不自动批准；逐项记保留/脱敏/排除理由与 hash。
旧来源 ID 可以作为明确历史来源，但不得暴露私人聊天或让公共导航依赖私有文件/网站。
维护历史 C-M9-002 BLOCKED 与当前 P 结果的区别，README 不将历史 −16.44% 写成当前包收益。
最终清单随内容变化重新校验；不得以 .gitignore 代替审查。

## E4：独立运行与真实读者

操作手册（第二台机器步骤、记录表、读者任务书）：[E4-RUNBOOK.md](E4-RUNBOOK.md)。

把生成包解压到 out 下的全新测试目录，从不同工作目录启动，禁止依赖原构建目录、源目录、开发 PATH 或用户缓存。
测试至少包含双后端启动、Demo 事件、退出/资源诊断，以及文档所要求的资源路径；记录实际命令、环境、退出码和包 hash。
优先由第二台符合最低需求的 Windows 机器运行；如果只有同机干净环境，明确验证边界，不声称跨机器/全新系统已通过。
请所有者安排一名未参与实现的真实读者，按包内 README 完成下载/解压/启动/查找证据，记录实际误解和成功/失败。
agent 自查或模拟读者不能替代真实反馈。联系他人/发送文件需所有者指示，未安排读者则保留待办。
根据反馈修复并重新生成包；字节变化后旧 SHA 和相关测试不能直接复用。
