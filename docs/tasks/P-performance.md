## 串行步骤

1. **P1 焦点诊断。** 在正式数据之外做短诊断，记录时间、前台切换和目标 PID，必要时退出后解析进程；原始信息仅本地保留。分别检查启动未获前台、采样中途失焦、窗口最小化/尺寸变化。当前只能证明失焦，不能预设原因是用户、通知或 agent。诊断开销不能偷偷进入正式计时路径。
2. **P2 启动方式与预演。** 准备所有者从独立本地终端启动的静默脚本：进度写日志，采样期间 agent 不弹窗、不启动交互 shell 或其他负载，结束再汇报。系统通知/电源设置若需调整，由所有者明确确认；不全局强抢/锁定焦点。验证故意失焦能失败、未就绪不采样、正常启动能完成；做覆盖完整配置顺序和切换的耐久预演，再估算全程时间。短预演通过不保证长采样必过。
3. **P3 协议和准备工具。** 把目前仅留 out 的构建准备逻辑整理为可复用、路径可配置的仓库工具；新建目录失败即停，检查空下载、路径逃逸、链接/联接点和输入 hash。保留源快照、依赖、实际编译器/构建命令、环境、EXE、烘焙输入。当前 driver 硬编码 002，不能原样复用；003 若被占用则选择未用新 ID。同时核对采集器、验证器、分析器和测试的身份契约。
4. **P4 冻结。** 默认沿用 002 的五 cell、五随机完整区组、25 次进程、120+600 帧、1920×1080、D3D12、VSync off、GPU 覆盖与前台门槛。确有设计问题时，在新正式采样前说明理由和变更；不得根据已有部分运行的性能数值优化规则。先分离完成 debug 正确性与无 debug 计时预演，再冻结协议及采集器/分析器 hash。先完成准备，再确认实际前台时段，不能继续沿用上一任务的时间授权。
5. **P5 正式采样。** 不同时构建、Capture、录屏或编码。保持每 run 唯一身份、顺序、完整 raw 和失败记录；失败按协议停止，不补跑拼接，不从 001/002 抽样。出现新失败先诊断，不循环占用整段机器时间。关闭强制前台门、暂停/筛掉失焦帧不算旧设计下的修复。
6. **P6 复算和表达。** 从逐帧输入重算每 run 分布，再以 run 为单位聚合；按预注册处理漂移、CPU p95、有效 GPU、内存池和尾部指标。负结果 REJECTED 或不确定 INCONCLUSIVE 均照实写。输出完整各 run 和比较，不挑最好一组，不作零分配、零泄漏或通用加速承诺。
7. **P7 收口。** 新当前结果使用独立声明身份；历史 C-M9-002 及原摘要不倒填。逐文件脱敏、绑定原始/公开文件 hash，公开复算输入足以在不访问私有仓库时验证结论。同步静态性能报告、路线图和候选清单。
