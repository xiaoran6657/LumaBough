# F：授权发布、匿名访问与下载核验

状态：待 E 的具体候选通过且所有者授权。先准备和审查，再执行外部写操作，最后实际核验。
GitHub CLI 已曾可用且登录，新 agent 仍须重新检查当前账户与权限；登录不等于发布授权。

## F1：锁定具体发布提案

读取 E 的实际候选报告和 hash，确认当前源码、Git ref、包与证据未漂移。
仓库名称建议使用 LumaBough，但 GitHub 名称可用性、账户和目标 URL 未确认；先只读查询，不把 MiniEngine 地址当发布目标。
提案列清：账号/仓库、创建与否、public/private、推送分支/ref、tag/release 名、源码清单、实际附件名/大小/SHA-256、Release 文案和已知限制。
旧 Git 历史不进入新仓库；禁止镜像推送或修改 MiniEngine 可见性。
先完成许可/隐私/候选审查及可审阅草稿，再向所有者申请覆盖这些具体动作的授权。
授权后按已确认范围执行，不因文档有“F 发布”字样就认为已获授权；不重复询问已明确授权的动作。

## F2：发布与绑定

按授权创建/连接目标仓库、推送所审阅 ref，核验远端 tree 与文件清单；发布指定 tag/release 和候选附件。
如果授权仅私有推送，保持 private，公开动作仍待授权。
运行提交、证据记录提交、发布 ref 分开记录；不能重新给旧 raw 填入发布 SHA。
更新公共链接需要新文档提交时，记录与运行源码的关系，并在远端再次验证，不虚构同一 SHA 下的自引用证据。
保存实际远端 URL、commit/tag、发布附件 ID/hash和操作结果；附件未上传成功不能宣称发布完成。
失败则记录已执行部分和下一步，避免盲目重复创建、覆盖 tag 或强推。

## F3：匿名验证

使用无登录、无认证头、无登录 Cookie 的独立浏览器会话或独立 HTTP 客户端验证；
已登录 gh browse/浏览器能访问不算匿名可达，浏览器退出登录不是必须方式。
核对仓库页面、README 图片/链接、性能证据、视频、Release 和每个附件；检查实际内容、重定向和下载结果，不只看 HTTP 200。
实际下载公开包，核对与 E 完全一致的 SHA-256，在新解压目录运行约定 smoke/Demo；远程文件和本地候选分别记录 hash。
无 GPU 的远端环境不能代替 Windows 双后端运行测试；确实无法执行时保留具体阻断并请求人工复验。
公开原始材料若涉及大文件下载/许可限制，按发布提案范围验证，不临时扩大上传集合。

## F4：完成条件与事故处理

完成条件：授权范围执行完毕、远端 ref 正确、源/附件集合与批准范围一致、匿名浏览和实际下载通过、下载包 hash/运行验证通过，已知限制明确。
当前校验器没有 published 阶段；新增机制需有测试，或交付完整手工核验记录；不能把 entry=PASS 改写为已发布。
发现错包、泄漏或损坏时立即停止继续发布，保留最小诊断并通知所有者；具体撤回/删除/历史重写按已授权回退方案或再次明确授权处理。
最终交付公共 URL、运行源码提交、发布 ref/tag、下载附件 hash、匿名验证时间/方法/结果、未闭合限制。
只有这些真实成立才把路线图 F 标为完成；“已推送”不等于“已验收公开发布”。
